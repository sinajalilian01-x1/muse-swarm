## Mainnet status of the contract fixes

The live contract `swarm.hlpok1lad.tg` has **not** been redeployed with the contract fixes yet. Its only access key is a full-access key (`ed25519:3gBbpdhY…`) that is not on the deployment machine, and the contract has no owner-gated upgrade method, so the owner account `hlpok1lad.tg` cannot deploy code to it. The new code changes logic only (no new state fields, no Borsh layout change), so it can be deployed in place without a migration once that key is available: `near deploy swarm.hlpok1lad.tg contract/target/wasm32-unknown-unknown/release/muse_swarm.wasm` (built from `bd37c6c` with Rust 1.96, sha256 `5755aa0b…685b561f`).

Until then, the off-chain fixes close every path the review found through the web app, and these live mitigations are in place:

- **MS-01:** the owner raised `budget_cap` from 0.5 to 5 NEAR with `update_rules` (mainnet tx [`2ntohqkB…`](https://nearblocks.io/txns/2ntohqkB3fsQY9VRJdPqqzBo4Y3zQWuchzT67Hb1pcSN), 14 Nov 2026 17:29 CET). Robot budgets are 0.04–0.20 NEAR, so a griefer would now have to donate about 5 NEAR into a robot budget (which the owner can withdraw) to trigger the old underflow. The site's Back button also refuses top-ups above the cap.
- **MS-05:** the guardian key is only used by the server, and the server now enforces the cooldown from the contract's `paused_until`.
- **MS-08 / MS-09:** the engine never asks the contract to expire a minted job, so the old contract's stranding path is not reachable from the app.

## What did not change

The review's positive controls still hold: robot and guardian keys are function-call keys with method allow-lists, no secrets are in the client or git history, the cron routes fail closed without `CRON_SECRET`, and the bounty payout stays a hard 0.02 NEAR from a purse that holds one payout.
